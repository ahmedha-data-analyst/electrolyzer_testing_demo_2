# HydroStar NextGen dashboard — local Demo mode (app_v2)

`app_v2.py` is a fully offline demo of the "NextGen Electrolyser Testing and
Validation" dashboard. It simulates all 16 process instruments shown on
NX-PID-001 so the layout, alarm colours, thresholds, trends and event log can
be reviewed before the physical sensors and live-data architecture exist.
Nothing is uploaded anywhere; no credentials, Supabase or Raspberry Pi are
used. Every value is generated locally and labelled SIMULATED.

## Folder contents

```
project/
  app_v1.py                              # earlier cloud-connected version (unchanged, not used by demo)
  app_v2.py                              # the Demo-mode dashboard (this app)
  provisional_sensor_registry_v2.yaml    # sensor metadata (16 instruments) — required
  logo.png                               # HydroStar logo — optional (text fallback if absent)
  NX-PID-001_prototype.pdf               # reference P&ID (not read by the app)
  requirements.txt                       # demo-only dependencies
  README_LOCAL.md                        # this file
```

## Run it

```
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app_v2.py
```

The browser opens on a live view that refreshes every 5 seconds. The
registry YAML must sit in the same folder as `app_v2.py`.

## Using the demo

- **Scenarios** (sidebar): "Mixed alarm demonstration" (default) shows green,
  amber, red and grey together; "Normal operation"; level / temperature /
  pressure excursions and a gas-crossover event that ramp NORMAL, H, HH;
  and a "Data-quality fault" with missing and stale readings.
- **Reset demo** regenerates the six-hour history for the current scenario.
- **Trend sensors**: pick one or two sensors and a 5 min / 15 min / 1 h / 6 h
  window. Threshold lines appear only where limits are configured.
- **Downloads**: current snapshot, windowed history and the alarm-event log
  as CSV.

## What the labels mean

- **SIMULATED** — the value was generated by the demo engine, not measured.
- **No approved limits** (grey) — all four limits are null for that sensor
  (flows, conductivity); it is deliberately never shown green.
- **UNKNOWN** (grey) — the reading is missing, stale or bad, so no alarm
  comparison is made.
- Alarm boundaries are inclusive: a value exactly on H/HH/L/LL takes that
  state. All limits are provisional dashboard values for behaviour testing,
  not PLC/SIS or approved trip settings. The dashboard is monitoring only —
  it issues no control commands and is no substitute for plant interlocks.
